二、上传到你的 GitHub 仓库
目标仓库：https://github.com/CJT-github/Focus-Island
工程已上传到该仓库；后续更新请使用 CJT-github 或有写入权限的账号。

解压工程包，进入能看到 Cargo.toml 的目录。代码应直接位于仓库根目录，
不要多套一层 FocusIsland-source 文件夹。必须包含隐藏目录 .github：
  .github/workflows/package.yml
  Cargo.toml / Cargo.lock
  src/ / ui/ / tools/

首次获取现有工程：
  git clone https://github.com/CJT-github/Focus-Island.git
  cd Focus-Island

在已有克隆中更新后推送：
  git add Cargo.toml Cargo.lock src ui tools .github .gitignore README.md PACKAGING.txt PROMPT.md tray-icon.png
  git commit -m "docs: update packaging and verification notes"
  git push

Git 会使用你已配置的身份和登录方式；若提示认证，在 GitHub 的浏览器授权中完成，
不要把密码、令牌或本机 state.json 放入工程。若仓库已有提交，应先取回并合并，勿强制覆盖。
也可在 GitHub 的 Upload files 页面上传同一组文件；务必保留 .github/workflows 的目录结构。

三、触发构建并下载
推送源码、文档或打包脚本会自动触发 Build desktop packages；也可在仓库 Actions 中选择该流程，
通过 Run workflow 手动启动。
流程包含 Windows x64、macOS arm64、macOS x86_64 三个任务，失败会保留日志。
构建成功后，在该次运行页面的 Artifacts 区域下载：
  FocusIsland-windows-x64
  FocusIsland-macos-arm64
  FocusIsland-macos-x86_64
  FocusIsland-source
Windows 产物是便携 ZIP；Mac 产物包含 .app 的 ZIP、DMG 与 SHA256。
新增的 FocusIsland-source 包含完整工程 ZIP 和对应的 .zip.sha256 校验文件；平台产物名称不变。
产物保留 14 天，不会自动发布 GitHub Release。

Mac 打包先执行 Rust 测试、编译、独立配置下的 GUI 自检；自检失败不会输出正式包。
这些检查不能代替真实鼠标穿透、Retina/多屏、系统权限提示和桌面动画的实机验收。
此前云端构建已通过；本轮顶部距离改动和新增工程产物流程尚待 CI 运行，请以对应提交的运行结果为准。

四、本机打包
Windows（需要 Rust MSVC、C++ Build Tools、Windows SDK）：
  powershell -ExecutionPolicy Bypass -File .\tools\package-windows.ps1
  powershell -ExecutionPolicy Bypass -File .\tools\package-windows.ps1 -SkipBuild

Mac（需要对应架构 Mac、Xcode Command Line Tools、Rust、Python 3.11+）：
  python3 tools/package-macos.py --target aarch64-apple-darwin
或 Intel Mac：
  python3 tools/package-macos.py --target x86_64-apple-darwin

重新生成工程 ZIP（Windows）：
  powershell -ExecutionPolicy Bypass -File .\tools\package-source.ps1

五、平台差异
Windows 使用 WebView2，目标电脑需要安装 Microsoft Edge WebView2 Runtime；
Mac 使用系统 WKWebView，无需安装 Edge。
Windows 配置目录：%APPDATA%\FocusIsland
Mac 配置目录：~/Library/Application Support/FocusIsland

Windows 自定义动作使用 PowerShell；Mac 使用 /bin/zsh，工作目录为用户主目录。
两种命令类型分开保存，不自动把 PowerShell 改成 Shell 执行。
Mac 可选择 Shell、睡眠、关机、重启；现代 macOS 锁屏动作暂不提供。
Mac 系统动作可能触发“自动化”授权；取消、拒绝或系统限制会在任务状态中反馈。
“距顶部”支持整数 0–1000 px，默认 20；点击“应用”或按 Enter 后立即生效并保存，不重置计时。
Windows 以所在显示器顶部为基准，按工作区上下边界约束实际位置，为展开圆盘保留空间；
Mac 以菜单栏下方的可用区域顶部为基准。保存的设定值不因屏幕约束改变。设置浮窗仍位于右下角。

Mac 包仅带 ad-hoc 本地签名，未使用 Developer ID、未经过 Apple 公证；
首次打开可能需要在系统隐私与安全性设置中允许。工程不会关闭 Gatekeeper。
正式向其他用户分发时，可另外配置 Developer ID 签名和公证。

Android 通知伴侣（第一版）
--------------------------
源码位于 android/，Android 8.0（API 26）起，targetSdk 36。
Windows 的手机通知模块使用 BLE GATT；macOS 手机接收和 iPhone ANCS 尚未实现。
本地构建：powershell -ExecutionPolicy Bypass -File .\android\build-local.ps1
标准构建：进入 android 目录，配置 JDK 17 / Android SDK 后运行 gradlew.bat testDebugUnitTest lintDebug assembleDebug。
测试 APK：android/app/build/outputs/apk/debug/app-debug.apk。
本地交付副本：dist/FocusIsland-Companion-android-debug.apk，使用 Android debug 签名供安装联调。
正式上架或长期自动更新需要自行配置稳定的发布签名；签名文件、SDK、Gradle缓存与local.properties不进入源码包。
新增 .github/workflows/android.yml，生成 FocusIsland-android-companion 测试包和校验文件；无需仓库写入权限，不发布到应用商店。
不同构建环境的 debug 签名可能不同，不能保证直接覆盖已有测试安装。

实机验收至少包含：系统配对、指定电脑授权、首次通知、中文和emoji、同通知更新/撤销、任务进行中独立通知岛展示、手动阅读不中断倒计时、手机锁屏、省电策略、蓝牙关闭恢复、手机停止共享、撤销通知权限、电脑休眠恢复。自动化协议/界面测试不替代这些实机步骤。
Webhook 接入与部署
--------------------------
桌面新增“Webhook”菜单：本机/局域网接收、专属地址、飞书文本消息格式、令牌更换及测试消息。
默认关闭，首次保存生成随机令牌；消息与手机通知共用“通知框”，不执行任务命令。
功能面板包含倒计时、Webhook、手机通知、通用设置四个顶级菜单；通知框开关、停留时间、列表数量和测试通知统一位于“通用设置 → 通知框”。
Windows 便携包和完整工程包均包含 deploy/relay 中继部署资料；deploy/webhook 与 tools/webhook-tunnel.ps1 保留为高级转发选项。
公网服务 https://webhook.tchenmm.online 已上线；在程序中填写该 HTTPS 服务地址与连接密钥即可自动连接，日常不使用 SSH。
自行部署其他服务器仍需准备 Linux 服务器与域名，按 deploy/relay/README.md 首次安装。
已完成实际 HTTPS → Windows 桌面通知 → ACK 验收，以及同 ID 消息更新、撤回、停用后恢复接收和应用重启后的待收消息续收验证。
服务器队列仅存内存；这里的重启续收指桌面应用重启，服务端重启会清空待收消息。
填写公网基地址本身不会部署服务器。真实 .env、令牌、SSH 私钥、用户配置与测试消息不进入包。
Mac 接收服务使用跨平台 Rust TCP 实现；本轮完成 macOS ARM/Intel 编译检查，未执行新的 macOS 云端构建；最新 Mac GUI 与公网实机验收仍需对应环境。Android 真机蓝牙验收尚未完成。
